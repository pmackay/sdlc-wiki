## 1. Identity & philosophy

Agent OS is a lightweight, open-source system for defining, documenting, and **injecting your coding standards** into AI coding agents, plus a structured way to **shape specs** for spec-driven development. As of v3 it is **not** a full scaffolding/orchestration framework — it deliberately defers implementation, task-tracking, and orchestration to modern agent tools (Plan Mode, todo lists, frontier models) and concentrates on capturing an organization's conventions and feeding the right ones into context at the right time. Tool-agnostic (Claude Code, Cursor, Windsurf, Codex, Antigravity, or "any AI assistant that reads markdown files") and language/framework-agnostic.

Signature framing (verbatim):
- "Every time you prompt an AI coding agent, you're re-teaching it context that should already be known."
- "a lightweight system for defining and managing your coding standards in AI-powered development."
- Repo: "Agent OS is a system for injecting your codebase standards and writing better specs for spec-driven development."
- README tagline: **"Agents that build the way you would."**

Author: **Brian Casel**, founder of **Builder Methods** (also ships [[bm-skills]]). License: **MIT**. Stars: ~5,167 (814 forks) at capture. Version history: v1.0.0 (2025-07-21), v1.4.0 (2025-08-17, Base+Project installs, Project Types), v2.1.0 (2025-10-21, 4→6 phases, Skills support), **v3.0.0 (2026-01-20)** the refocus.

Positioning: deliberately does **less** than Spec Kit or BMAD. "Rather than competing with modern AI tools on scaffolding tasks, v3 concentrates on what the framework does best: establishing standards, injecting them smartly, and enhancing spec-driven development."

## 2. The three-layer context / standards model

All stored as plain Markdown/YAML in a project-local `agent-os/` folder.

### Layer A — Standards (the defining feature)

"Standards are declarative documentation of your coding conventions. They describe patterns and rules — 'our API responses use this format' — without prescribing procedures."

- Location: `agent-os/standards/`, organized hierarchically by domain (e.g. `api/response-format.md`, `database/migrations.md`, root-level `naming-conventions.md`).
- Authoring guidance (verbatim): "Standards are injected into AI context windows. Every word costs tokens. Keep them concise." — lead with the rule, prefer code examples, "Document only unconventional patterns, not framework defaults."
- **The index — `agent-os/standards/index.yml`:** maps each standard to a one-sentence description so agents can *match* relevant standards without reading every file. Alphabetized; `root` first.
- Authored semi-automatically via `/discover-standards` (drafts from existing code + "why" questions) or by hand + `/index-standards`.
- Read on demand via `/inject-standards` (auto-suggested or explicitly named) and during `/shape-spec`. Standards use **explicit invocation** (Skills auto-detect; standards do not).
- **Refined over time:** refine in-project, then **sync back to a reusable profile** via `~/agent-os/scripts/sync-to-profile.sh` (bidirectional; `--overwrite`). Core-loop phase 4 is literally "Refine — Update standards as patterns evolve."

### Layer B — Product docs

- Location: `agent-os/product/`. Created by `/plan-product`.
- Files: `mission.md` (vision, target users, core problems), `roadmap.md` (phased feature plan, MVP vs post-launch), `tech-stack.md` (stack choices).
- Read by `/shape-spec`.

### Layer C — Specs

- Location: `agent-os/specs/`, one **timestamped folder per spec**: `YYYY-MM-DD-HHMM-{feature-slug}/`.
- Files: `plan.md` (full plan), `shape.md` (scope, decisions, context), `standards.md` (snapshot of relevant standards), `references.md` (pointers to similar code), `visuals/` (optional).
- Produced by `/shape-spec` in Plan Mode; persist beyond the conversation.

## 3. Commands (exhaustive — five, no instructions/agents folders in v3)

Core loop (verbatim): "1. Discover — Extract patterns from your codebase into documented standards. 2. Inject — Deploy relevant standards when you need them. 3. Build — Work with your AI tools using those standards. 4. Refine — Update standards as patterns evolve."

- **`/discover-standards`** — extract tribal knowledge from the codebase into concise standards. 6 phases: focus-area selection (AskUserQuestion) → pattern analysis (reads 5-10 files, finds unusual/opinionated/tribal/consistent patterns) → per-standard development (1-2 "why" questions, draft, confirm, one at a time) → file creation → index update → offer next area. Writes `agent-os/standards/[folder]/*.md` + updates `index.yml`.
- **`/inject-standards`** — deploy relevant standards into current context. Auto-suggest (bare) or explicit (`/inject-standards api/response-format`). 3 steps: context detection (coding vs skill vs planning) → matching against `index.yml` descriptions (presents 2-5 to confirm) → injection (Conversation mode loads full content; Skill/Plan mode offers **file references** vs **embedded snapshots**). Also surfaces relevant Skills without auto-invoking.
- **`/index-standards`** — maintain `index.yml` (standard → one-sentence description). Scan → diff → propose descriptions for new files (user-confirmed) → remove stale → write alphabetized (`root` first). `/discover-standards` runs it automatically as its last step.
- **`/plan-product`** — establish foundational product docs via interactive conversation (AskUserQuestion, one question at a time). 6 steps: check existing → gather vision → gather roadmap → establish tech stack → generate `mission.md`/`roadmap.md`/`tech-stack.md` → confirm.
- **`/shape-spec`** — shape specs **in Plan Mode** (hard-stops if not in plan mode: "Shape-spec must be run in plan mode."). 9 steps: clarify scope → gather visuals → identify code references → read `agent-os/product/` → surface standards from `index.yml` → generate timestamped folder → structure plan (**Task 1 is always "Save spec documentation"**) → remaining tasks → confirm. Writes the spec folder.

**No execute/deploy command.** Building happens in the agent tool using injected standards + the shaped plan; task tracking left to the agent's own todo lists.

## 4. Sub-agents

**None in v3.** "While Agent OS no longer installs subagents, you can create your own." (v2 shipped context-fetcher, file-creator, git-workflow, test-runner, project-manager — all retired.) Commands use the host tool's **AskUserQuestion** tool instead of delegated sub-agents.

## 5. Default standards content & profiles

Ships minimal default content — expects you to *discover* your own. Only committed default standard: `profiles/default/global/tech-stack.md` (React 18 + TS, Tailwind v4, Vite; Node + Express + TS; PostgreSQL).

**Profiles** are reusable base-installation collections of standards (`~/agent-os/profiles/`, e.g. `default/`, `rails/`). "A profile is a named collection of standards in your base installation." Override per project: `project-install.sh --profile rails`; `default_profile` in `~/agent-os/config.yml`; **profile inheritance** (`inherits_from`, child overrides parent on duplicate filenames); push refinements back via `sync-to-profile.sh`.

## 6. Lifecycle shape

Standards core loop: Discover → Inject → Build → Refine. Homepage framing: Install → Discover → Inject → Shape. End-to-end: Install → `/plan-product` → `/discover-standards`+`/index-standards` → `/shape-spec` (Plan Mode) → `/inject-standards` → Build (in the agent tool) → Refine + sync-to-profile.

**Explicit gaps by design:** no deploy step, no dedicated review/verification command, no formal retrospective command. Nearest to "learning" is the Refine + sync-to-profile loop; nearest to "verification" is standards-as-guardrails + the shaped plan (the v2 test-runner agent was removed).

## 7. Distinctive mechanisms

- `index.yml` as a **token-efficient matcher** — load only relevant standards by one-line description.
- **Two injection payload modes** — file references (auto-current) vs embedded snapshots (self-contained/versioned).
- **Standards vs Skills** as a first-class distinction: "Standards describe *what* conventions to follow. Skills describe *how* to do tasks." Declarative + explicit-invocation vs procedural + auto-detected. Skills can reference standards.
- **Bidirectional profile sync** — refine in a project, promote to a reusable base profile; inheritance chains. The framework's answer to "how do standards get better over time."
- **Deliberate minimalism / delegation to the model** — v3 *removed* its own scaffolding: "Claude Code's plan mode, extended thinking, and improved models now handle much of the scaffolding that earlier versions of Agent OS provided."
- **Discovery with "why" interrogation** — documents only unusual/opinionated/tribal patterns, capturing rationale.

## 8. The v2 → v3 shift

Older write-ups describe v2: commands `plan-product`, `analyze-product`, `create-spec`, `create-tasks`, `execute-tasks` + sub-agents (context-fetcher, file-creator, git-workflow, test-runner, project-manager). **v3.0.0 (2026-01-20)** retired the implementation/orchestration phases, replaced spec-generation with Plan Mode (`/shape-spec`), removed sub-agents, added `/discover-standards` + `/inject-standards` + `sync-to-profile`, consolidated profile inheritance into `config.yml`. "Content remains compatible … but commands and scripts are substantially different."

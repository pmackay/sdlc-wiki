## One-line identity

A deliberately **minimal, model-agnostic terminal coding-agent harness**: four built-in tools (read, write, edit, bash) and everything else pushed into a TypeScript extension system. "The strength is in what they didn't build."

## Interaction surface

Primary/native = **terminal TUI**. Also print/JSON modes for scripting, an **RPC** mode (JSON over stdin/stdout), and an embeddable **SDK**. No first-party IDE/desktop/web GUI.

## Model access

**Model-agnostic / multi-provider** via a unified LLM API (`@earendil-works/pi-ai`): Anthropic, OpenAI, Google, Azure, Bedrock, Mistral, Groq, Cerebras, xAI, Hugging Face, Kimi For Coding, MiniMax, NVIDIA, OpenRouter, Ollama, plus custom providers via extensions. Mid-session model switching.

## Execution primitives — a MINIMAL core (this is the signature)

- **Sub-agents/agents** — NO in core (**intentionally excluded**); available via extensions/third-party packages.
- **MCP** — NOT in core (intentionally excluded); available via extensions. (medium confidence on exact current extension surface)
- **Hooks** — via the **extension** system (TypeScript modules), not a named hooks API. (medium confidence)
- **Custom slash-commands** — YES: **prompt templates** (Markdown under `~/.pi/agent/prompts/` or `.pi/prompts/`, invoked `/<template>`) and **skills** invoked `/skill:name`.
- **Skill/command format** — YES: **Skills** (capability packages under `~/.pi/agent/skills/` or `.pi/skills/`); project config via **AGENTS.md** and **SYSTEM.md**; themes; prompt templates.
- **Permissions/approval** — NO built-in permission popups (**intentionally excluded**); relies on containerization/sandboxing or extensions for boundaries.
- **Plan mode** — NO built-in plan mode (intentionally excluded); via extension.
- **Session persistence/resume** — YES: sessions with **tree-structured, shareable history**, stored at `~/.pi/agent/sessions/…`.
- **Memory/context files** — YES: AGENTS.md + SYSTEM.md loaded from `~/.pi/agent/`, parent dirs, and cwd; **context compaction** with customizable summarization.

## Extensibility / distribution

Open-source (MIT). npm package `@earendil-works/pi-coding-agent` (older `@mariozechner/*` imports still work). Monorepo: `@earendil-works/pi-ai` (LLM API), `pi-agent-core` (runtime), `pi-coding-agent` (CLI), `pi-tui` (terminal UI lib). Extensibility via **TypeScript extensions** + **SDK**; a **Rust implementation** also exists (supports skills/prompt templates). Install via npm/pnpm/bun or curl/PowerShell.

## Distinctive

**Radical minimalism** — only 4 core tools; MCP, sub-agents, permission popups, plan mode, to-dos, and background bash are deliberately left OUT of core and delivered as opt-in extensions. Notable pedigree (libGDX's Zechner + Flask's Ronacher at Earendil).

## Wiki cross-references

- Spawned by runtimes: a provider in Sandcastle; a harness option in Warren (claude-code/sapling/pi).
- Officially a target of cross-harness frameworks (e.g. Superpowers names Pi).
- Patterns it provides as core primitives: session-handoff (tree-structured resumable sessions + compaction), context-engineering (AGENTS.md/SYSTEM.md + skills + compaction). It does NOT provide fresh-context-subagents or edit-guardrails as core primitives — those are extension territory, the clearest example in the wiki of a pattern that is a harness primitive in one harness and absent from another.
